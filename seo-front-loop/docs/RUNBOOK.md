# seo-front-loop：自然语言执行手册

数据工具已补充：先读 [配置与采集说明](../skills/seo-front-loop/references/data-tools.md)，使用 tools/collect_metrics.py 检查缺项，向用户收集信息和安全授权，再检查权限并采集基线/复查快照。该工具不依赖关键词文件已存在，不连接未经授权的账户，不写决策记忆。目前已完成离线测试，真实账户联调仍待用户提供授权。

版本：v1.4，2026-09-12。默认单 Agent 串行，以 Markdown 记忆执行。原数据库接口、JSON 实验规范、事务和租约测试不再是当前实施要求。当前没有真实站点记忆、指标连接、自动调度或生产发布。

## 1. 新任务怎么开始

先确认用户指的是哪个项目。存在多个候选且用户未明确时，按 [项目协议](../skills/seo-front-loop/references/projects.md) 列出名称并询问，不自动读取其他项目记忆。所有命令的 --project 必须传选定项目目录；各项目的关键词、记忆和凭据独立，不沿用上一轮目标。

使用 seo-front-loop Skill，并指明管理项目、实际站点与本轮目的。先读 [Skill](../skills/seo-front-loop/SKILL.md) 和其必读 [自然语言协议](../skills/seo-front-loop/references/protocol.md)，再读取 config、关键词、站点说明与相关完整记录。不能只凭当前聊天总结。

首次未接管站点时可做只读研究。只有用户要求接管/实施时，才核对实际域名、产品仓库、GSC 属性、部署方式、已有改动与未知历史，按证据建立 Markdown 站点说明。不得把示例或空目录当成已经接管的真实站点。

## 2. 可用工具

当前仅提供只读配置和纯日期算术脚本，不提供实验状态服务、记忆解析器、强制历史门禁或部署接口。运行方法见 [README](../README.md)。

脚本读取 config 和 seo-keywords.json。对旧实验，先从 Markdown 原记录核对上线确认时间、当时采用的间隔与最多次数；如需日期算术，显式同时提供 --live-verified-at、--interval-days 和 --max-checks。遗漏任何一项会报错，不回退到当前全局周期。

不再支持 --record 或 --now，也不创建 JSON 记忆或从自然语言自动推断状态。日期结果是临时计算输出；Agent 将核实后的日期和决定写回原 Markdown。日期经过不自动解除限制。

## 3. 一项改动如何记录

使用 [自然语言模板](../skills/seo-front-loop/assets/改动记录模板.md) 的问题作为提示，不要求特定字段、标题、枚举或 YAML 头部。

用完整句子说明目标、原因、用户关键词、证据、改前改后准确原文、必要配套、影响及禁止项、原历史关联、授权和检查。未上线时如实说明；真实上线后记录完整日期、时区、代码版本和回执，再算复查日期。

观察约定包括本次间隔和次数、固定查询/页面组、数据窗口、主要与保护指标、样本和干扰限制。缺少转化埋点就承认无法验证转化，不能写成已通过。

每轮有授权的实际操作/复盘，用短 Markdown 运行记录说明读过什么、采取/拒绝什么、下一步是什么；纯解释或状态查询保持只读，不因 Skill 而擅自记账或改站。

## 4. 四个阶段，不是四个 Agent

### 观察

先核对线上与记录，优先处理未确认部署、已知事故和数据问题。采集只走已授权来源，失败不当零，不覆盖旧快照。未到复查日且没有异常时无需重新研究或改文案。

### 决策

先读全相关历史，再决定无修改、继续观察、需要补证据或提出一项干预。对照八类修改范围，明确属于修复、优化实验或结构项目。多个独立优化不借共同“提升 SEO”打包。

保留用户关键词；新的词表只进入未来候选，不修改旧实验已约定的查询组。重试旧策略需要实质新证据，不能只换名称和措辞。

### 执行

确认没有另一个写入者，核对当前文件和生产基线，按已批准范围编码、自检和测试。常规小改不强制子 Agent；失败策略重试、规则例外、超频或高影响操作需要独立复核/人工，不能以自检冒充。

只有既有权限允许才发布，记录部署意图、准确版本、回执和线上确认。未知结果先对账，不重复发布。修改前后原文和证据写入正式 Markdown，再更新导航索引。

### 复查

按原约定第 20/40/60 天或该实验明确采用的周期复查；先核实数据、上线与干扰，再解释结果。到期不代表能判定、也不代表应该再次改动。

无结论且继续等待有价值则保持原样到下一日期；最后仍无结论就结束常规等待，保留正确且无已知损害的版本和重开条件。部署未知/事故未恢复先处理，不以期限耗尽解除保护。

结果只对本次完整干预负责，组合成员独立效果未知。更正追加日期、原判断和原因，不覆盖历史；必要回滚检查是否会损害其他人的后续工作。

## 5. 用户简报

用几句话说明：本轮结论；当前真实版本；上次改什么；本轮改了/没改什么及原因；用户词如何处理；证据窗口及不足；当前限制；下次检查日期或条件；原记录链接。没有变化不写成长报告。

例如（虚构）：首页仍为 B。上次改动尚在观察，没有新证据支持改成 C，因此本轮不修改；下一次按原约定日期复查。实际记录中附对应原文、日期和证据，不只保留这句摘要。

## 6. 实施顺序

1. 核对站点和历史，建立可信、有缺口说明的 Markdown 接管记录。
2. 用虚构资料演练读记录、拒绝重复、追加复查和换任务恢复。
3. 按授权接入 GSC 等数据，保存原始证据。已有 PostHog 时先核验事件/归因，再判断是否需要其他站内分析源。
4. 经授权做一项小范围改动，验证代码与真实上线，写完整记录。
5. 按周期复盘，证明“不该动时不动”。
6. 确有定时需求时另接调度、防重叠执行和私有备份，不自动扩大改站权限。

这不是必须建设数据库或多 Agent 管理平台的清单。无需预先重建旧自治循环和后台界面。

## 7. 行为验收场景

以下是待验证的 Agent 行为，不声称 Python 单元测试已经实现这些保护。

| 场景 | 期望行为 |
| --- | --- |
| A 改 B 后尚在观察，又建议 C | 读取原记录并保持 B，说明限制依据 |
| 很久前已试过 A，当前建议回到 A 或近义 A | 搜索并阅读完整相关历史，解释是否需要有证据重开 |
| 多个成员换名、拆轮重放旧组合 | 关联整体和成员历史，不当全新策略 |
| 改 config 为 5 天，但旧记录明确为 20 天 | 按旧记录继续；用户改旧计划需追加理由和前后约定 |
| 原文日期或时区有矛盾 | 先核实，不猜起点和是否到期 |
| 索引说可改，正式记录仍在观察 | 对账后更正索引，不取更宽松结论 |
| 部署成功但未记完就中断 | 根据准确版本/回执恢复，不重复发布 |
| 第 60 天数据不足且部署状态未知 | 先对账并保持保护，不自动关闭 |
| 错过两个检查点 | 当前只复查一次，说明漏检，不伪造旧结果 |
| 没有数据或接口失败 | 不填零、不把无结论记失败 |
| 必要事实/技术修复影响观察范围 | 按授权修复并关联中断；不为维持实验而保留错误 |
| 人工修改了同页或共享模板 | 记录实际影响，保留人类改动，不静默覆盖 |
| 组合上线后增长 | 只记组合结果，不产生各成员独立成功规则 |
| 换任务、上下文压缩或恢复备份 | 重新读原记录和证据，继续识别限制 |
| 接管后丢失历史 | 恢复/核实，不重新初始化清空过去 |
| 两个任务同时想写 | 当前模式停止冲突写入并协调，不声称 Markdown 提供硬锁 |
| 只问状态或解释 | 保持只读，不擅自写记忆、连接账户或改站 |
| 未启动子 Agent 的普通小任务 | 单 Agent 可以完成；独立复核仅在既定条件触发 |

## 8. 当前交付边界

已提供自然语言记忆协议和模板、更新后的 Skill、明文配置/关键词读取与日期计算工具。没有创建真实站点记忆、数据库、调度、外部连接或生产变更。

单元测试验证配置优先级、错误输入、关键词校验、日期算术以及拒绝旧实验 JSON 参数；行为验收和真实 SEO 收益需另外验证。此次本地调整不自动提交或推送 GitHub。

## 仓库与提交记录

config 的 SEO_REPOSITORY_URL 填实际网站源码仓库，目前未确认，暂留空。Agent 先核对本地 remote 与站点对应关系，并通过已有授权检查目标仓库可读；推送另需写权限和用户授权。明文 config 不保存凭据。

自然语言记录关联完整改前/改后 commit ID 与提交链接。未提交明确说明并保存 Diff，不擅自生成提交；多个提交、合并后 ID 变化及回滚都追加对应关系。实际部署提交和线上验证独立记录。commit 不能替代理由、指标和观察限制。完整规则见 [记忆协议](../skills/seo-front-loop/references/protocol.md)。

验收还应覆盖：配置仓库不匹配、无读取/写入权限、未提交、squash 后追溯、多提交混入业务改动、提交已合并但尚未部署、回滚不覆盖其他改动。单元测试仅验证配置格式，不证明真实 GitHub 权限或上述行为已验证。
