# 自然语言记忆与复查协议

所有决策记忆使用普通 Markdown 自然语言。不要创建数据库、实验 JSON、YAML 头部、状态字段表或另一份机器可写账本。标题和段落只是便于阅读，不是解析器必须匹配的格式；具体原文、时间和证据仍须准确。

## 配置与记忆分开

管理项目的 config 保存可提交 Git 的明文设置，仅复查周期优先级为进程环境变量、config、默认值；项目身份、账户、关键词/记忆路径和凭据变量名称使用选定项目 config，不允许跨项目环境覆盖。脚本不执行文件内容，不读取旧 .env，不输出其他环境变量或密钥。

- SEO_REVIEW_INTERVAL_DAYS：新实验复查间隔，默认 20 天，支持整数 1–365。
- SEO_REVIEW_MAX_CHECKS：最多检查点，默认 3 次，支持整数 1–12。
- SEO_KEYWORDS_FILE：用户词表，默认 seo-keywords.json。
- SEO_MEMORY_DIR：自然语言记忆的私有持久目录，默认 .seo-memory。

config、关键词 JSON 和 API 原始 JSON/CSV 是配置或数值证据，不属于决策记忆，不强行改为散文。Skill 发现元数据也不是实验记忆。脚本输出仅为临时工具结果，不保存成第二份权威状态。

GSC/PostHog 的额外配置、秘密环境变量及缺项询问集中在 [数据工具说明](data-tools.md)。tools/collect_metrics.py 默认本地检查，不要求所有可选服务齐备；经授权才能查询实际账户或保存独立证据快照，工具不写自然语言决策记忆。

采用某周期时，在改动记录中写清“本次每 20 天复查，最多 3 次”，同时保留用户当时实际采用的关键词与评估查询口径。之后更改 config 或词表不改变原约定；明确调整旧计划时追加日期、前后约定、原因和授权，不覆盖旧段落。

## 文件组织与依据

先按 [项目选择与隔离](projects.md) 明确当前项目。同一站点所有任务和源码 worktree 共用一个稳定管理项目目录及其中的私有记忆；不同站点分别设项目目录、关键词和记忆。按实际接管需要创建，不因安装 Skill 就建立虚构历史。

- 站点说明.md：域名、产品仓库、部署方式、接管时间、历史可信边界、未知部分和单写入者约定。
- 记忆索引.md：页面、当前限制、下一检查时间和原记录链接，只用于导航，不另作独立决策。
- 改动记录/E001-首页标题.md：每项改动一份正文，包含提案、执行、上线、复查和更正。
- 运行记录/日期-任务名称.md：本轮读过哪些记录、做了什么、哪些建议没做及原因。
- 证据/：脱敏指标快照、原文、Diff、线上回执等原始工件。

正式依据是改动记录与证据。索引和正文矛盾时先核实，不选更宽松的一个放行；索引可重建，历史不能因此丢弃。运行记录尽量简短，无变化时无需重复一大段分析。

## 每次记录说清什么

可参考 [自然语言模板](../assets/改动记录模板.md)，措辞和段落顺序不必相同，不强制机器字段。

说明页面、历史 URL、关联旧记录；为什么改、实际关键词、证据与未知项；修改前后准确原文、主改动、必要配套及未修改项；实际影响页面、内链两端、共享组件及对照保护；当前做到哪一步；完整上线日期与时区、代码版本与回执；当时约定的周期、最多次数与检查日期；指标、窗口、固定查询口径；当前限制和重开条件；每次复查的结果及下一步。

大段内容/代码链接完整 Diff，不仅写“优化了标题”。未确认的写“尚未确认”，不能把模板、当前日期或估计时间当成真实上线证据。

## 防止 A→B→C→A

每轮先读站点说明和索引，再按页面、历史路径、共享组件和意图查找并读完相关记录，包括拒绝、失败、回滚和已结束记录。搜索命中只是入口，不只看最新一轮或摘要；过长时分批读，覆盖不明时允许研究但暂停改站。

本轮写清：以前是否出现过目标原文或相同策略？判断依据是哪几份记录？哪些限制仍有效？本次新增什么事实？不要只匹配字符串，也要识别近义反复和不断改写却从不复盘的情况。

观察期间默认保护整页、相关共享影响和对照；保留的稳定版本无新证据不重改。关闭后默认再保护 14 天，同页滚动 90 天第 3 次常规实验需重新评估并独立复核。时间过去、模型更换、词表重新保存不自动算新证据。

必要修复、回滚和新条件下的重试引用原记录、新证据、授权及范围。组合的结果只适用于组合，成员独立效果未知；组合失败不证明所有成员无效。组合换名或拆成多轮重做仍需检查整体与成员历史。

新结论追加带日期的段落；纠正旧判断时指明原段落与理由，不抹掉过去。顶部可以有当前摘要，但需链接最新决定，不替代历史。

## 复查与恢复

默认从真实上线确认起第 20/40/60 天复查。Agent 从自然语言原记录确认时间和当时周期，不用当前 config 替换旧约定。需要算术辅助时，向日期计算器显式传入上线时间、间隔和次数；它不解析记忆、不判断状态、不授权修改。原记录有矛盾或时区不清时先核实，不猜到期。

每次核对上线与搜索处理，再检查最终数据、实际窗口、样本和干扰。到期不一定能判定，更不自动允许重改。搜索处理慢不重置时钟；继续观察沿用原检查日。多次累计窗口不是独立证据，正式统计检验需预先处理重复检验。

错过多个检查点只做一次当前复查，写明漏检，不补造旧报告。最后仍无结论且没有未知部署/未恢复事故时关闭常规等待，保留正确且无已知损害的版本和重开条件。真实新证据出现时可追加复评。

必要工程修复不等复查日，按既有权限处理并记录影响实验中断；工程成功与搜索收益分开。未知部署先对账并保持保护，不因期限已到就解除。恢复时核实实际版本，不重复发布，不用旧文件覆盖人类后续修改。

## 可靠性和迁移边界

当前只有一个主写入任务、人工控制发布；自然语言“正在观察”不是硬锁。未来定时执行须另配不重叠运行和持久存储，不能声称文件存在就保证没有竞争；本次不实现或启用这些设施。发现其他任务或人工修改先对账。

写入前重读最新相关记录，先追加事实与决定，再更新导航。中途退出时依据正文、证据和备份恢复；接管后丢记录必须恢复，不重新初始化清空限制。首次未知旧历史则明确记录可信边界，不伪造过去。

如发现旧 JSON/数据库记忆，先只读转换为可核对的 Markdown，保留原文件与证据，核对无遗漏后明确切换；不要自动删除、覆盖或双写。本项目当前没有真实站点账本需要迁移。

对记忆和证据做私有可恢复备份，忽略 Git 不等于备份。不要保存密钥或不必要个人数据。Skill 不会自行醒来；用户要求调度时再用宿主机制，只报告重要变化、故障或所需决策。读取/解释请求不授权改站、记账或发布。

## 仓库权限与 commit 追溯

SEO_REPOSITORY_URL 保存实际网站源码仓库的无凭据 https://github.com/OWNER/REPO 地址，可带 .git。默认留空，未确认前不改站。其他托管或企业域名需另行适配。核对 config、实际网站和本地 remote：HTTPS 与 SSH remote 可指向同一仓库，应比较主机和 owner/repo。不要输出带凭据的 remote。配置改变不能重写旧记录的仓库归属。

通过已有授权连接器或本机登录做只读检查，例如 gh repo view OWNER/REPO --json nameWithOwner,url,viewerPermission，并读取相关提交或 Diff；参数来自已校验配置。gh 未安装可用已有连接器或 Git，不自动安装、登录、创建令牌或改 remote。公共仓库可读不证明有写权限，gh auth status 成功不证明特定私有仓库可读。无法读取必要历史时报告缺少的权限，只做规划，不凭缺失历史继续改站。

推送前另确认写权限、分支保护和本次用户授权；按仓库规则走 PR。访问权限不是提交、推送、合并或部署授权，不通过实际试推送探测权限。凭据不写 config 或记忆。

每份改动记录写仓库地址、修改前完整 commit ID、修改后完整 commit ID 和 GitHub 提交链接。一个实验可关联多个提交，分别说明作用；若混入业务改动，明确实验路径和 Diff 范围。未提交写“尚未提交”并保存 Diff，不虚构 ID，不为填记录擅自提交。无代码改动的复查、否决提案无需空提交。

squash、rebase 或 cherry-pick 改变 ID 时，核对 Diff 后追加原提交与最终合并提交的对应关系。部署另记实际部署 commit、线上确认时间及证据；commit、push、合并时间均不等于上线时间。回滚用新提交关联原提交和记录，不删除失败历史，不盲目还原旧版本覆盖其他工作。

commit 只证明代码，不替代原因、观察限制和复查结论。权限丢失或提交不可访问时保留私有 Diff 备份并先核对，不视为“从未修改”。私有记忆不自动推送公开仓库。
