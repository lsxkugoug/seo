# 用户关键词与修改范围

## 用户输入格式

词表是管理项目配置，不放在 Skill 全局目录里，以免不同站点串词。用户可直接修改 JSON；也可要求 Agent 保存某组关键词。未经要求不重写用户列表，不把自己的建议自动混入用户原始偏好。

以下只是语法示例，不是本项目已经选定的关键词：

```json
{
  "primary": ["PDF 转 Word", "在线 PDF 转换"],
  "secondary": ["PDF 转 Word 保留格式"],
  "excluded": ["破解 PDF 软件"],
  "page_targets": {
    "/pdf-to-word": ["PDF 转 Word", "PDF 转 Word 保留格式"]
  },
  "notes": "优先中文用户；是否支持保留格式需要核实产品事实。"
}
```

primary 为优先研究词，secondary 为辅助/长尾词，excluded 为不主动优化的方向（不是禁止引用该字符串，也不是自动删文指令）。page_targets 是期望页面映射，不证明页面存在或应该新建。空数组有效，表示尚未指定；只做基线/研究，不虚构用户的业务方向。包含和排除同一规范化词时脚本报错，需解决冲突。

## 关键词如何影响决策

1. 保留用户原词、优先级和配置版本。先处理其方向，不悄悄换成流量更大但不相关的词。
2. 核实产品是否真实满足该需求、页面是否存在、语言/地区是否匹配；查看可用 GSC 查询、落地页、公开 SERP 意图。未接数据时承认需求/竞争未知，不捏造搜索量、排名、竞品私有指标。
3. 按搜索意图分组并映射现有页面。不要按每个近义词创建一页；同意图多页先检查是否合理分工或互相蚕食，未经授权不合并/删除。
4. 返回词级处理状态：采用、需要证据、当前不适合；每项给原因。用户坚持的词可作为明确业务要求，但不能因此编造功能、评价、认证或搜索效果；不能支持的承诺需先澄清事实。
5. 选定某词不意味着所有位置都要出现。根据缺口择一改 title、一个内容模块或必要入口；自然表达，不设固定关键词密度/重复次数目标，不复制竞品文案。
6. 提案保存用户词表快照及实际评估查询组，二者不是同一个概念。观察期间新增关键词只进未来候选，不能替换旧查询组改善分数；确认业务方向变化需有记录地关闭/中断旧实验后重新立项。

## 八类干预的最小完整单位

| 主类别 | 合理单位 | 影响/验证注意 |
| --- | --- | --- |
| metadata | 一个页面的一种摘要表达，优先 title 或 description 单项 | H1、正文也可能影响搜索展示；默认保护整页 |
| content | 解决一个具体问题的完整说明、例子或 FAQ 模块 | 必要小标题、配图、样式可联动；禁止借此重写全页 |
| structure | 一段阅读/查找路径或层级调整 | 同时改文案/CTA 时声明组合，不能归因于结构单项 |
| internal_links | 一组明确来源→目标关系 | 纳入两端、共享导航消费者和对照污染；看相关组总量 |
| structured_data | 一个真实且一致的实体/关系 | 核对当前受支持类型及资格；正确标记不保证展示收益 |
| crawl_index | 一个已证实根因与必要一致性修复 | canonical/robots 一行也可能影响全站；工程恢复与搜索恢复分开 |
| performance | 一个已定位瓶颈及必要配套 | 可重复实验室诊断和可用真实用户数据分开，不把跑分当排名收益 |
| page_lifecycle | 一个意图对应的完整上线/迁移包 | 路由、跳转、canonical、Sitemap、入口按依赖处理；看新旧 URL 和意图组净变化 |

共同目标“提升 SEO”不足以打包独立改动。配套项须说明：不做它，主改动为何无法正确上线/使用。确要组合多个独立优化，需明确批准并仅评价组合整体。第一版优先低风险摘要/内容；高影响模板、索引策略、迁移另立项目和独立复核，不能因用户给了关键词就自动升级范围。

## 核实易变规则

涉及搜索展示、Schema 资格和具体技术规则时，使用当前官方资料并保存 checked_at 与来源。旧经验到期需复核，不自动重复试验。可按需查看 [标题链接](https://developers.google.com/search/docs/appearance/title-link)、[摘要](https://developers.google.com/search/docs/appearance/snippet)、[结构化数据规则](https://developers.google.com/search/docs/appearance/structured-data/sd-policies) 与 [搜索变化诊断](https://developers.google.com/search/docs/monitor-debug/debugging-search-traffic-drops)。不要把旧 FAQ 富媒体展示经验直接作为当前收益依据。
