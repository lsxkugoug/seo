# Blog Generator 验证协议

本协议用于回归测试 Skill 的主题研究、编辑决策和集成边界。测试通过表示规则能约束输出，不代表文章会获得排名或流量。

## Hard failures

出现任一项即不允许接入自动发布：

- 把只换年份、受众、数字标题或 slug 的明显变体判为 `new`。
- 忽略 archived、merged 或 redirected 内容历史。
- 库存不完整或相近正文未读，却设置 `publish_allowed: true`。
- 虚构产品能力、实测、排名、数据、来源、URL 或第一手经历。
- 用关键词不同代替正文级任务比较。
- 没有先建立网站/用户任务主题地图，就只从给定库存机械换词选题。
- 将 Semrush 估算指标、竞品页面或 GSC 的短期波动当成搜索效果已被证明的结论。
- 把草稿推送 API 当成发布授权，或在失败后无幂等保护地重复推送。
- 声称增加内部链接数量会必然增加权重、排名或曝光。
- 未进行目标市场的 SERP 审计，就把关键词工具的 intent 标签直接当作文章结构。
- 将竞品近期新增页面、趋势信号、图片数量或“前十都有”当成已证明会带来流量或排名的结论。

## 回归案例

至少覆盖：

1. 年份变体应 `update/merge`。
2. 只有受众标签、没有专属材料时应 `update/merge/defer`。
3. 标题不同但正文步骤相同时不得建立新 URL。
4. 有真实场景约束、原始材料和独有阅读产物时可以有条件 `new`。
5. “我们测试了 N 款工具”但没有原始输入输出时应 `needs_evidence`。
6. 开头承诺必须映射到正文段落。
7. 内链应有方向、位置、读者需要和描述性锚文本。
8. 缺少库存时只能输出 provisional 候选，`publish_allowed: false`。
9. 批量更换年份和受众时应返回去重矩阵，不生成平行正文。
10. 与合并或重定向历史碰撞时，应更新 canonical 目标或继续合并。
11. 内容需要合并但页面冻结时，应同时输出 `content_disposition: merge` 和 `execution_status: frozen`。
12. 没有文章库存的新网站，应能从产品、受众和 SERP 提出 provisional 主题，但不能批准新 URL 发布。
13. 竞品覆盖某词但本站没有独有任务、材料或产品事实时，应 `defer`，而不是改写竞品文章。
14. Semrush 显示高 volume、但产品不支持或 SERP 意图不匹配时，应拒绝或标记 `needs_evidence`。
15. 历史库存 API 缺少 archived、merged、redirected 或关键正文时，应阻断 `publish_allowed`。
16. 推送提案返回 `pending_review` 时，输出已交接而非“已上线”；同一幂等键重试不得创建第二篇提案。
17. GSC 评估应保存页面/查询组、日期、国家、设备、数据完整性与同期干扰；曝光增加不能单独判为成功。
18. 内链计划必须给出来源、目标、位置、读者需要和描述性锚文本；不得用未发布 URL 或“权重提升”作为理由。
19. SERP 审计必须保存查询、市场、时间、审阅数量、主导意图、共同必要内容块和未满足需求；提纲应能说明哪些部分来自共同任务，哪些是本站的独有贡献。
20. 竞品近期页面或趋势词只能形成候选假设；产品不匹配、没有独有材料或 SERP 形式不支持时应 `defer` 或 `needs_evidence`。
21. 媒体建议必须说明其解释的步骤、状态、差异或证据；“多放图会提高排名”应判为失败。

## 真实库存验收

接入 Generator 前，在完整站点库存上测：

- 已知重复文章的 Top-3 候选召回率；
- 已知重复被误判为 `new` 的比例，目标为 0；
- 同一输入重复运行三次的 disposition 与 gate 一致率；
- `closest_candidates` 是否包含正文审查证据；
- live、archived、merged、redirected 数量能否对账；
- 三篇完整文章的匿名 A/B 审查，包括任务清晰度、独有材料、开头承诺、事实风险和可操作性。

小规模上线后再按预先定义的业务指标、搜索指标和保护指标评估效果。文章数量不作为成功指标。
